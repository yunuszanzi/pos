# v0.2.0: Catalogue and stock

Builds on v0.1 (sign-in, users, roles, organisation, audit log). Nothing in v0.1 changed for users.

## What you can do

- **Maintain the catalogue.** Categories (nested), brands, tax categories with editable rates, units of measure, products with one or more SKUs, and per-SKU cost, sale price, barcode and reorder level.
- **Sell in several units.** Each SKU can have a base unit (piece) and larger units (pack, carton) with a conversion factor, its own barcode and its own price. Stock is always kept in the base unit: 10 cartons of 200 is 2,000 pieces.
- **Import and export products by CSV.** Choose a file and every problem is listed by row and column before anything is saved; the import is all-or-nothing. Importing an existing SKU updates it, and empty cells leave current values alone. Exports can be re-imported without changing anything.
- **Load opening stock** by CSV, in any unit the product is sold in, with an optional cost per unit.
- **Follow stock.** Levels per SKU and location (with a breakdown in larger units and low-stock flags), a permanent movement history with a running balance, and valuation at cost and at sale price as of the end of any day.
- **Adjust stock with control.** Record damage, loss, found stock or a count correction. Above a value you set in Settings (default PKR 10,000) the adjustment waits for someone with approval rights; stock changes only when it is approved. Rejections need a reason. Stock can never go below zero.
- **Price lists** with quantity breaks, such as a lower carton price from 10 cartons.
- **Print barcode labels** on A4 sheets (24-up or 40-up, with a start position for a partly used sheet) or a 50 × 30 mm roll. Valid EAN-13 codes print as EAN-13, others as Code 128. The product form can generate an internal EAN-13.

## Who can see what

Cost prices, average cost, stock value and valuation need `products.cost.view` (Owner and Manager have it; Cashier does not). Cashiers can look at products, stock and price lists but cannot change them.

New permission keys: `catalog.view`, `catalog.manage`, `products.cost.view`, `products.import`, `products.export`, `inventory.view`, `inventory.adjust`, `inventory.approve`, `inventory.opening_stock`. Existing businesses get them on upgrade; custom roles are unchanged.

## Upgrading

Run `npm run db:migrate`. Migrations `0002` (catalogue and stock) and `0003` (ledger sequence) are applied in order. Existing businesses receive the standard tax categories, units and the new permissions for their Owner, Manager and Cashier roles. This is tested on a database that already holds a v0.1 business.

Check after upgrading: **Categories & tax** has a "Reduced rate" of 5% that is a placeholder, and the FBR sale type names are typed from memory. Confirm both with your tax advisor; v0.8 syncs them from FBR.

## Fixed

- A malformed id in a v0.1 address such as `/branches/abc` now answers "not found" instead of a server error.

## Not in this release

FIFO costing as a setting (weighted average is built), product image upload and a SKU attribute editor (the fields exist and import/export keep them), reorder levels per location, and applying a price list to a sale, which arrives with the POS in v0.3.

## Acceptance tests

1. Import 500 products from CSV with a preview of errors; fix and re-import.
2. Opening stock of 10 cartons (200 pieces each) shows as 2,000 pieces.
3. An adjustment above the threshold stays pending until a manager approves; the ledger and balance change only after approval.

All three run in a real browser against the real API and database.
