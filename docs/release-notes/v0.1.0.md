# v0.1.0: Foundation

The base the rest of the system is built on.

## What you can do

- **Create a business.** The owner signs up, then sets up the business profile, a first branch, a stock location, a terminal and the invoice number series.
- **Manage staff.** Invite users by email, give them a role, restrict them to branches, deactivate them without losing history, and generate a password-recovery link. System roles are Owner, Manager and Cashier; the Owner can build custom roles from a permission matrix and edit them later.
- **Switch users at a terminal** with a 4 to 6 digit PIN, and approve restricted actions with a manager PIN. PIN attempts are rate-limited.
- **Configure** locale, rounding and session timeouts (30 minutes in the back office, 12 hours at the POS by default).
- **Review the audit log**, an append-only record of who did what, when and from which terminal, with before and after values.

## Security rules enforced

- Every API route checks permissions on the server; hiding a button is only a convenience.
- Nobody can manage a user, or grant a permission, that is above their own. A Manager cannot take over the Owner account.
- Data is isolated per business, and the browser has no direct access to database tables.
- A deactivated user is locked out at once.

## Fixed during hardening

PIN switching returned a server error because of how the attempt window was stored; it works and locks out after five wrong attempts. After a PIN switch the screen kept showing the previous user; fixed. Validation errors now say what is wrong instead of "Request failed (400)".

## Acceptance tests

1. The owner signs up, creates the business, a branch, a terminal and a cashier.
2. The cashier cannot open Users or Settings, in the screens or by calling the API.
3. A PIN switch changes the active user on a terminal, and the audit log shows both logins.

These run in a real browser against the real API and database.
